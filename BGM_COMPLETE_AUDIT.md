# BGM — Complete Feature Audit

Audit of the repository as found at commit `a1caf95` (before this work). Every item was found by reading the code path from the UI through the server action to Firestore. **Status** says what was done on branch `claude/bgm-production-readiness-kzs130`.

Roles: SA = Super Admin, O = Owner, T = Trainer, M = Member, All = everyone, Pub = unauthenticated visitor.

## Summary

| Severity | Found | Fixed | Open |
|---|---|---|---|
| CRITICAL | 14 | 13 | 1 (needs credential rotation by you) |
| HIGH | 27 | 25 | 2 |
| MEDIUM | 21 | 18 | 3 |
| LOW | 9 | 7 | 2 |

The single most important finding: **the application had no server-side authorisation.** The session was an unsigned JSON cookie, and almost every server action accepted ids from the browser and executed with the Admin SDK. Anyone could read or change any gym's data, or become Super Admin, with a hand-written cookie. The earlier impression that features "worked" came from testing as a well-behaved user.
